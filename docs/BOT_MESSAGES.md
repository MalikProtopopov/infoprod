# Сообщения Telegram-бота — карта всех текстов

> Документ для ревью и редактирования всего, что бот может сказать пользователю.
> Сгруппировано **по источнику** (где живёт текст) и **по сценарию**
> (что юзер увидит и когда). Дата актуальности: 2026-05-25.

---

## 0. Архитектура — где что живёт

```
┌─────────────────────────────────────────────────────────────────────┐
│                                                                     │
│  СТАТИЧЕСКИЕ ТЕКСТЫ                                                 │
│  backend/app/bot/texts.py            ← одиночные константы          │
│                                                                     │
│  INLINE-ТЕКСТЫ В ОБРАБОТЧИКАХ                                       │
│  backend/app/bot/handlers.py         ← «Заявка отправлена», ошибки  │
│                                                                     │
│  ТЕКСТЫ КВИЗА И ФОРМЫ                                               │
│  backend/app/services/step_flow.py   ← системные сообщения flow     │
│  funnel_steps.quiz_data  (JSONB)     ← вопросы, опции, вердикты     │
│  funnel_steps.form_data  (JSONB)     ← поля формы, success-сообщ.   │
│                                                                     │
│  СООБЩЕНИЯ ВОРОНКИ                                                  │
│  funnel_steps.message_text (БД)      ← D0/D1/D3/...                 │
│  funnel_step_media        (БД)       ← PDF/фото на шагах            │
│                                                                     │
│  ВОРКЕР                                                             │
│  backend/app/workers/scheduled_messages.py                          │
│      сам пользователю не пишет, только отправляет шаги воронки      │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

Чтобы поменять текст:

| Тип сообщения              | Где править                                     | Когда видит юзер                     |
| -------------------------- | ----------------------------------------------- | ------------------------------------ |
| WELCOME / HELP / системные | `backend/app/bot/texts.py`                      | `/start`, `/help`                    |
| Заявка отправлена, ошибки  | `backend/app/bot/handlers.py` (inline-строки)   | после нажатия кнопок                 |
| Сообщения воронки (Dn)     | админка → /funnels/{id}/edit, либо seed-скрипт  | по расписанию после старта воронки   |
| Вопросы квиза              | админка (когда подключим UI) или seed-скрипт    | после нажатия «начать тест →»        |
| Вердикты квиза             | то же                                           | после последнего ответа              |
| Поля формы                 | то же                                           | при заявке: 5 шагов сбора            |
| Системные ошибки квиза/формы | `backend/app/services/step_flow.py`           | при попытке отвечать в стухшей сессии|

## 1. Статические тексты (`backend/app/bot/texts.py`)

Это **строковые константы**, привязаны к точкам входа в бота.

### 1.1 `WELCOME`
```
Здравствуйте!

Через этот бот можно оформить доступ в закрытые каналы.
Выберите интересующий продукт из списка ниже.
```
**Когда:** `/start` без deep-link или `menu:main` callback.
**Под сообщением:** кнопки-каталог с продуктами (callback `prod:{id}`).
🟡 *Тон не совпадает с mediann-воронкой («на ты», lower-case). Если бот будет на 100% mediann-ным — переписать.*

### 1.2 `NO_PRODUCTS`
```
Сейчас нет доступных продуктов. Загляните позже.
```
**Когда:** в БД нет активных продуктов.

### 1.3 `HELP`
```
Команды:
/start — начать и посмотреть каталог
/my — мои подписки и сроки
/help — эта справка
```
**Когда:** `/help`.

### 1.4 `NO_SUBSCRIPTIONS`
```
У вас пока нет активных подписок.
```
**Когда:** `/my` для юзера без подписок.

### 1.5 `LEAD_SENT`
```
Спасибо за заявку! Администратор свяжется с вами в ближайшее время
и пришлёт условия оплаты.
```
**Когда:** нажал «📝 Оставить заявку» на карточке продукта (callback `lead:{id}`).
🟡 *Это старая ветка — «оставить заявку на продукт» без сбора данных. Для mediann-воронки используется отдельный form-flow с success-сообщением из form_data.*

### 1.6 `PRODUCT_NOT_FOUND`
```
Этот продукт сейчас недоступен.
```
**Когда:** продукт удалён / деактивирован между показом и кликом.

### 1.7 `LINK_EXPIRED_OR_INVALID`
```
Эта ссылка устарела или недоступна. Посмотрите наш каталог ниже.
```
**Когда:** `/start <arg>` с битым tracking-link slug / product code.

### 1.8 `CODE_WORD_ACCEPTED` ⚠️ — **именно это сообщение ты увидел**
```
Принято, сейчас пришлю материалы.
```
**Когда:** юзер написал триггер-слово (например «MVP»), бот распознал и
**запустил воронку**. Это **немедленный ответ**, до того как воркер
отправит D0 (см. §6 — диагностика).

### 1.9 `UNSUBSCRIBED`
```
Хорошо, больше не буду присылать напоминания.
Если что — напишите /start, всё снова заработает.
```
**Когда:** клик системной кнопки «🔕 Не присылать напоминания».

### 1.10 `product_card(...)` — динамический шаблон
HTML-карточка продукта: имя жирным, описание, ниже список «3/6/12 мес. — цена».
Если все цены нулевые: «Цена уточняется. Нажмите «Оставить заявку»…».

### 1.11 `access_granted(...)`
```
✅ Оплата принята.

Доступ к каналу «{channel_title}» открыт до {ends_at} UTC.
Ссылка‑приглашение (одноразовая):
{invite_link}
```

### 1.12 `access_expired(...)`
```
⏳ Срок доступа к каналу «{channel_title}» истёк.

Чтобы продлить доступ, нажмите /start и оставьте новую заявку —
администратор пришлёт реквизиты для оплаты.
```

### 1.13 `my_subscriptions_line(...)`
Формат `• «{channel}» — {status_label}, до {date}` для `/my`.

| handlers.py:511   | `Подписал вас на серию сообщений ✓`         | toast после успешной подписки на воронку через кнопку                 |
| handlers.py:549   | `Не нашёл квиз`                             | toast при битом `quiz:start:{step_id}`                                |
| handlers.py:560   | `Квиз сейчас недоступен`                    | toast если шаг квиза неактивен / нет questions                        |
| handlers.py:587   | `Этот тест уже не активен`                  | toast при попытке ответить в законченном/отменённом квизе             |
| handlers.py:590   | `Не удалось обработать ответ`               | toast при системной ошибке квиза                                      |
| handlers.py:602   | `Не нашёл форму`                            | toast при битом `form:start:{step_id}`                                |
| handlers.py:613   | `Форма сейчас недоступна`                   | toast если шаг формы неактивен / нет fields                           |

> Toast = всплывающее уведомление Telegram. Используется когда юзер
> нажал callback-кнопку — поверх чата на пару секунд появляется текст,
> в чате ничего не остаётся.

## 3. Сообщения квиза/формы (`backend/app/services/step_flow.py`)

### 3.1 Прогресс-строки

| Контекст        | Формат                                       | Пример                       |
| --------------- | -------------------------------------------- | ---------------------------- |
| Вопрос квиза    | `{prefix-из-quiz_data}\n\n{text-вопроса}`    | «вопрос 1/5\n\nможешь...»    |
| Поле формы      | `{idx+1}/{total}\n\n{question}`              | «1/5\n\nкак зовут?»          |

### 3.2 Кнопка отмены формы (любое поле)
```
❌ отменить
```
callback `form:cancel:{state_id}` — переводит state в `cancelled`.

### 3.3 Если поле формы пустое / «-»
```
это поле обязательно. ответь по существу — потом сможем продолжить.
```
**Когда:** юзер прислал «-», «нет», «skip» или пустую строку на обязательное поле.

```
пожалуйста, ответь текстом — это поле обязательно.
```
**Когда:** прислал пробельную строку.

### 3.4 Cancel-сообщение формы
Берётся из `form_data.cancel_message`. Дефолт (если не задано):
```
Отменено. Когда будешь готов — наберёшь /start.
```

### 3.5 Success-сообщение формы
Берётся из `form_data.success_message`. Дефолт (если не задано):
```
готово, заявка принята.
```

### 3.6 Фоллбэки квиза (на пустые вердикты)
```
Тест завершён. Балл: {score}.
```
**Когда:** в `quiz_data.verdicts` ни один не подошёл (защита от кривого seed).

## 5. Квиз Mediann (step_id=7, quiz_data) — **в БД**

### 5.1 Вопросы (5 шт., каждый «да=0 / нет=1»)

| # | Префикс           | Текст вопроса                                                                                 |
| - | ----------------- | --------------------------------------------------------------------------------------------- |
| 1 | вопрос 1/5        | можешь сказать гипотезу вслух за 10 секунд: «если [решение] → пользователь [действие] → это даст [измеримый результат]»? |
| 2 | вопрос 2/5        | у тебя есть метрика успеха = число + срок + сегмент (а не «всем понравится»)?                  |
| 3 | вопрос 3/5        | можешь назвать 5 конкретных людей, которые попробуют продукт первыми?                          |
| 4 | вопрос 4/5        | скоуп разбит на mvp / v1 / v2 и ты готов резать лишние фичи?                                   |
| 5 | вопрос 5/5        | знаешь, сколько готов потерять, если гипотеза не взлетит, и заложен ли 10% буфер?              |

Опции одни и те же на всех вопросах: `✓ да` (score=0) / `✗ нет` (score=1).
Итоговый score = сумма ✗ (0–5).

### 5.2 Вердикты (выбирается первый с `max_score >= score`)

| score | Текст вердикта                                                                                                    | Кнопка                  |
| ----- | ----------------------------------------------------------------------------------------------------------------- | ----------------------- |
| 0–1   | результат: 0–1 минус. ты готов делать mvp. следующий шаг — зафиксировать скоуп и вилку. оставь заявку…             | `оставить заявку →`     |
| 2–3   | результат: 2–3 минуса. идея живая, но есть слабые места — на них обычно и теряют деньги. ровно их разбираем…       | `разобрать слабые места →` |
| 4+    | результат: 4+ минусов. запускаться сейчас — риск слить бюджет. сначала закрой пункты из pdf (часть 1)…             | `получить приоритеты →`  |

Все 3 кнопки ведут на `form:start:6` (одна и та же форма-заявка).

## 6. Форма-заявка Mediann (step_id=6, form_data) — **в БД**

### 6.1 Поля (5 шт.)

| # | Ключ      | Вопрос                                                                          | Обязательное |
| - | --------- | ------------------------------------------------------------------------------- | ------------ |
| 1 | name      | как зовут?                                                                      | да           |
| 2 | stage     | что за продукт и на какой стадии? (идея / прототип / есть mvp — коротко)        | да           |
| 3 | problem   | что не получается прямо сейчас? пара предложений.                               | да           |
| 4 | contact   | как удобнее связаться? telegram-ник или телефон.                                | да           |
| 5 | link      | ссылка на лендинг / прототип / notion — если есть. (можно пропустить — отправь «-») | нет     |

### 6.2 Success-сообщение
```
готово. малик свяжется с тобой лично в течение 24 часов — назначим время разбора.

а пока можешь подготовиться: открой ссылку на прототип (если есть), пример конкурента, который нравится, и держи в голове 1 цифру — сколько готов вложить в проверку гипотезы.
```

## 7. Воркер `scheduled_messages` — пользователю не пишет

Воркер берёт `funnel_step.message_text` и шлёт юзеру через Bot API.
Никаких собственных текстов **не добавляет**. Если шаг провалился
(нет бота, юзер заблокировал и т.п.) — только пишет в лог и помечает
`ScheduledMessage.cancel_reason`. Юзер ничего не получает.

## 8. ⚠️ Диагностика: «почему пришло "Принято" вместо D0»

### Что произошло

| Время     | Событие                                                                       |
| --------- | ----------------------------------------------------------------------------- |
| 12:39:52  | Юзер написал `MVP` → bot нашёл триггер → создал `funnel_entry id=3`           |
| 12:39:52  | bot сразу ответил `texts.CODE_WORD_ACCEPTED = «Принято, сейчас пришлю материалы.»` |
| 12:39:52  | Воркер добавил 10 `scheduled_messages` (D0 с `scheduled_at = now`)            |
| 12:42:02  | **Следующий тик воркера (раз в 5 минут)** → отправил D0                       |

Так что **D0 пришёл — просто через ~2 минуты**. Это видно в логах:
`{"sent": 1, "cancelled": 0, "failed": 0, "batch": 1, "event": "scheduled_messages.processed"}`.

### Почему UX плохой

1. **Сообщение «Принято, сейчас пришлю материалы.»** — оно общее, плохо
   стыкуется с тоном mediann (на «ты», lower-case) и звучит как
   «всё, я закончил». Юзер думает «и это всё?».
2. **Воркер тикает раз в 5 минут** (`backend/app/workers/scheduler.py:53`).
   Для D0 с `delay=0` это **неуместно медленно** — кажется что бот залип.

### Что починить

| Приоритет | Изменение                                                                                                   | Файл                                                |
| --------- | ----------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| 🔴 High   | Слать D0 **синхронно** в момент старта воронки (если `delay_minutes=0`), не через scheduler                  | `app/services/funnels.py:start_for_user`            |
| 🟠 Med    | Заменить `CODE_WORD_ACCEPTED` либо удалить — если синхронный D0 заработает, лишний «Принято» не нужен        | `app/bot/texts.py` + `app/bot/handlers.py`          |
| 🟠 Med    | Ускорить воркер до 30 сек или 1 мин — для шагов с маленьким delay сейчас всё равно лаг                       | `app/workers/scheduler.py:53` (`IntervalTrigger(minutes=5)` → `seconds=30`) |
| 🟡 Low    | Перенести inline-строки `handlers.py` в `texts.py` — централизация                                           | `app/bot/handlers.py`                               |

## 9. Как редактировать тексты воронки

### Через админку (https://grammy.mediann.dev)
1. Войти под админом
2. Воронки → **Mediann · MVP pilot** → выбрать шаг
3. Изменить `message_text` / кнопки → Сохранить
4. **Не нужен** ни ребилд, ни рестарт — берётся из БД при следующей отправке

### Через seed-скрипт (для полной пересборки)
1. Отредактировать строки `D0_TEXT … D14_TEXT` / `QUIZ_DATA` / `_form_data`
   в `backend/scripts/seed_mediann_funnel.py`
2. `rsync` + `docker compose exec backend python -m scripts.seed_mediann_funnel --pdf /tmp/15-punktov.pdf`
3. ⚠️ Сидер **удалит** существующую `Mediann · MVP pilot` и пересоздаст
   её с нуля — все юзеры в активной подписке потеряют будущие
   запланированные сообщения. Хорошо для итераций до запуска, плохо
   когда уже есть живые юзеры.

### Через прямой SQL (точечные правки)
```sql
-- пример: поправить D0
UPDATE funnel_steps
SET message_text = '<новый текст>'
WHERE id = 8;
```
```sql
-- пример: поправить вопрос #3 квиза
UPDATE funnel_steps
SET quiz_data = jsonb_set(
  quiz_data, '{questions,2,text}',
  '"новый текст вопроса"'::jsonb
)
WHERE id = 7;
```
