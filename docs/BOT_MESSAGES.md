## 1. Хардкод в `app/bot/texts.py` (13 элементов)

Это **строковые константы**. Чтобы изменить — нужно отредактировать файл и задеплоить бэкенд.

### 1.1 `WELCOME`
```
Здравствуйте!

Через этот бот можно оформить доступ в закрытые каналы.
Выберите интересующий продукт из списка ниже.
```
**Когда:** `/start` без deep-link или callback `menu:main`.
**Под сообщением:** кнопки-каталог с продуктами (`prod:{id}`).

🟡 *Тон не совпадает с mediann-воронкой («на ты», lower-case). Если бот будет на 100% mediann-ным — переписать.*

### 1.2 `NO_PRODUCTS`
```
Сейчас нет доступных продуктов. Загляните позже.
```
**Когда:** в БД нет активных продуктов.

### 1.3 `HELP`
```
Команды:
/start — начать и посмотреть каталог
/my — мои подписки и сроки
/help — эта справка
```
**Когда:** `/help`.

🟡 *Команды описаны под «магазин подписок», для mediann-воронки звучит мимо.*

### 1.4 `NO_SUBSCRIPTIONS`
```
У вас пока нет активных подписок.
```
**Когда:** `/my` без активных подписок.

### 1.5 `LEAD_SENT`
```
Спасибо за заявку! Администратор свяжется с вами в ближайшее время
и пришлёт условия оплаты.
```
**Когда:** клик «📝 Оставить заявку» на карточке продукта (callback `lead:{id}`).

🟡 *Для form-flow используется отдельное `Form.success_message` из БД — у mediann-воронки оно настроено.*

### 1.6 `PRODUCT_NOT_FOUND`
```
Этот продукт сейчас недоступен.
```
**Когда:** продукт удалён/деактивирован между показом и кликом.

### 1.7 `LINK_EXPIRED_OR_INVALID`
```
Эта ссылка устарела или недоступна. Посмотрите наш каталог ниже.
```
**Когда:** `/start <arg>` с битым tracking-link slug / product code.

### 1.8 `CODE_WORD_ACCEPTED` — **подавляется при успешном sync-flush**
```
Принято, сейчас пришлю материалы.
```
**Когда раньше:** немедленно после распознавания триггер-слова → спойлерил D0.

**Когда сейчас:** только если sync-flush D0 ничего не отправил (например,
шаг с `delay_minutes > 0` или воронка отключена). При нормальном пилоте
mediann — это сообщение **больше не приходит**.

### 1.9 `UNSUBSCRIBED`
```
Хорошо, больше не буду присылать напоминания.
Если что — напишите /start, всё снова заработает.
```
**Когда:** клик системной кнопки «🔕 Не присылать напоминания» под любым шагом воронки.

### 1.10 `product_card(name, description, price_3m, price_6m, price_12m, currency)`
Динамический HTML-шаблон карточки продукта: имя жирным, описание, ниже список «3/6/12 мес. — цена». Если все цены нулевые: «Цена уточняется…».

### 1.11 `access_granted(channel_title, ends_at, invite_link)`
```
✅ Оплата принята.

Доступ к каналу «{channel_title}» открыт до {ends_at} UTC.
Ссылка‑приглашение (одноразовая):
{invite_link}
```

### 1.12 `access_expired(channel_title)`
```
⏳ Срок доступа к каналу «{channel_title}» истёк.

Чтобы продлить доступ, нажмите /start и оставьте новую заявку —
администратор пришлёт реквизиты для оплаты.
```

### 1.13 `my_subscriptions_line(channel_title, ends_at, status)`
Формат `• «{channel}» — {status_label}, до {date}` для команды `/my`.

## 2. Inline-тексты в `app/bot/handlers.py` (12 фраз)

| Файл:строка       | Текст                                       | Контекст                                                              |
| ----------------- | ------------------------------------------- | --------------------------------------------------------------------- |
| handlers.py:286   | `Ваши активные подписки:`                   | Заголовок ответа `/my`                                                 |
| handlers.py:362   | `Заявка отправлена`                         | Toast после клика `lead:{id}`                                          |

| handlers.py:549   | `Не нашёл квиз`                             | Toast при битом `quiz:start:{step_id}`                                 |
| handlers.py:560   | `Квиз сейчас недоступен`                    | Toast если шаг квиза неактивен / нет questions                         |
| handlers.py:587   | `Этот тест уже не активен`                  | Toast при попытке ответить в законченном/отменённом квизе              |

## 3. Хардкод в `app/services/step_flow.py` (системные)

Появляются когда юзер делает что-то не так в квизе/форме или контейнер пуст.

### 3.1 Динамические шаблоны

| Контекст        | Формат                                       | Пример                       |
| --------------- | -------------------------------------------- | ---------------------------- |
| Вопрос квиза    | `{prefix}\n\n{text-вопроса}`                 | «вопрос 1/5\n\nможешь...»    |
| Поле формы      | `{idx+1}/{total}\n\n{question}` или с префиксом | «1/5\n\nкак зовут?»       |

### 3.2 Системные строки

| Строка                                                                                              | Когда показывается                                                |
| --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| `это поле обязательно. ответь по существу — потом сможем продолжить.`                                | Юзер на обязательное поле прислал «-», «нет», «skip», «пропустить» |
| `пожалуйста, ответь текстом — это поле обязательно.`                                                 | Юзер прислал пробельную/пустую строку                              |
| `Отменено. Когда будешь готов — наберёшь /start.`                                                    | Фоллбэк cancel-сообщения формы (если `Form.cancel_message` пуст)   |
| `готово, заявка принята.`                                                                            | Фоллбэк success-сообщения формы                                    |
| `Тест завершён. Балл: {score}.`                                                                      | Финал квиза при пустом `quiz_verdicts` (защита от seed-ошибок)     |
| `❌ отменить`                                                                                       | Текст кнопки отмены формы на каждом поле                           |

## 4. Хардкод в `app/workers/scheduled_messages.py`

### 4.1 Системная кнопка под каждым шагом воронки

InlineKeyboardButton(

    callback_data="unsubscribe_notifications",

## 8. Точки старта воронки → точки sync-flush

Все 4 места, где у юзера может стартануть воронка, теперь сразу sync-отправляют шаги с `delay=0`:

| Точка                                              | Файл:строка                  | sync-flush      |
| -------------------------------------------------- | ---------------------------- | --------------- |
| Deep-link `/start <tracking_slug>`                 | handlers.py:208 → :230       | ✅ перед catalog |
| Триггер-слово (например «MVP»)                     | handlers.py:443 → :462       | ✅ + supressнес «Принято» |
| Кнопка `funnel:start:{id}` в любом шаге            | handlers.py:498 → :515       | ✅              |
| Авто-старт `default_funnel` при создании Lead      | handlers.py:357 → :375       | ✅              |

Подразумевается, что у funnel есть шаг с `order_idx=0, delay_minutes=0` (как D0 в mediann-пилоте). Если все шаги с ненулевым delay — sync-flush ничего не отправит, и юзер получит первое сообщение по тику scheduler'а (теперь 30 сек вместо 5 мин).
