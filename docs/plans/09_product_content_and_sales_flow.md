# 09. Контент продукта + ведение горячего лида к заявке

> Цель: при `/start` бот ведёт пользователя как «живой менеджер» — приветствие →
> разделы → каталог → карточка продукта с презентационным контентом (кружок/видео/
> галерея фото/голос + стилизованный текст с раскрывающимися цитатами) → заявка по
> конкретному продукту. Контент продукта гибко настраивается в админке. После покупки —
> благодарственное сообщение.
>
> Ветка: **`feature/product-content`** (создана). Этот файл — план; реализация по фазам.

---

## 0. Принципы (продажи горячим лидам)

В продукт приходят **горячие лиды** — значит:
1. **Быстро к ценности и оферу.** Минимум кликов до презентации и CTA «Оставить заявку».
2. **Одна явная цель на экран** (one primary CTA). Не распыляем внимание.
3. **«Живость».** Контент приходит как живые сообщения: индикатор «печатает…/записывает кружок…»,
   небольшие задержки, отдельные сообщения разных типов (текст → кружок → видео → фото).
   Это повышает вовлечение и доверие.
4. **Нет тупиков.** На каждом шаге есть «‹ Назад / 🏠 Меню» и понятный следующий шаг.
5. **Низкое трение заявки.** Заявка — в один тап, данные тянем из Telegram (без форм, если не нужно).
6. **Гибкость контента.** Менеджер собирает презентацию продукта в админке без кода.

Связь с существующим: каталог + заявки уже есть; воронки (drip, по времени) — для
**пост-касаний после заявки**. Эта фича — **синхронная презентация по запросу** (при открытии
продукта), не drip. Обе системы дополняют друг друга.

## 2. Чего не хватает (делаем)

1. **`video_note` (кружок)** и **`voice` (голосовое)** в отправителе бота (сейчас
   `ALLOWED_MEDIA_TYPES` = photo/video/animation/audio/document/voice — voice есть в типах,
   но sender его не шлёт; video_note отсутствует вовсе). `infer_media_type` не различает их —
   тип «кружок» задаётся **явно** менеджером (это mp4, отправляемый методом `sendVideoNote`).
2. **Контент-модель продукта** — упорядоченная последовательность блоков презентации.
3. **Синхронный поток презентации** при открытии продукта (не scheduled).
4. **«Живость»** — `send_chat_action` + задержки между сообщениями.
5. **Благодарственное сообщение** после покупки (стилизованное).
6. **Главное меню/разделы** при `/start` (настраиваемое приветствие + кнопки).

## 3. Модель данных (рекомендация)

### 3.1. Поля продукта (простые, всегда)
Добавить в `products`:
- `card_text` (Text, styled HTML) — основной текст карточки в боте (с цитатами/спойлерами).
  Если пусто — fallback на текущий `description` (plain).
- `thank_you_message` (Text, styled HTML) — отправляется после покупки (в `subscriptions.grant_for_payment`).
- `presentation_enabled` (bool, default true) — слать ли блоки презентации при открытии продукта.

### 3.2. Блоки презентации (гибкая последовательность) — `product_content_block`
Упорядоченные блоки, доставляются по очереди при открытии продукта (ощущение «живого» диалога):

| Поле | Тип | Назначение |
|---|---|---|
| id | PK | |
| product_id | FK → products (CASCADE) | |
| order_idx | int | порядок отправки |
| kind | str: `text` \| `media` \| `media_group` \| `video_note` \| `voice` | тип блока |
| text | Text (HTML) | текст блока (или подпись к одиночному медиа) |
| delay_ms | int (default 800) | задержка перед отправкой (имитация набора) |
| is_active | bool | |

Медиа блоков — отдельная таблица **`product_media`** (зеркало `funnel_step_media`), FK на
`product_content_block` (или на product + block). Поля как у funnel_step_media: media_type
(+ **`video_note`**), storage_path, order_idx, caption, mime, size, width/height/duration,
telegram_file_id, thumbnail, checksum.

> **Решение №1 (подтвердить):** контент-блоки vs. «плоские» поля.
> - *Блоки* (рекоменд.) — максимально гибко: текст между медиа, любой порядок, эффект живого диалога.
> - *Плоские поля* (проще) — у продукта одна галерея + один кружок + один текст + thank-you.
> Беру за основу **блоки** (отвечает требованию «гибко» и «как будто человек пишет»).

> **Решение №2:** переиспользовать ли `funnel` вместо новой сущности? — Нет: воронка drip/
> по времени и привязана к лиду; презентация синхронна и привязана к продукту. Шарим только
> **медиа-модель и sender**, а не сущность funnel.

## 4. Бот — навигационный поток

```
/start [slug]
  │
  ├─ (1) Приветствие (styled WELCOME) + reply-кнопка «🏠 Меню»
  ├─ (2) Главное меню (inline «разделы»): [📦 Продукты] [ℹ️ О нас?] [💬 Контакты?]
  │        — минимум «Продукты»; остальные секции опциональны/настраиваемы (Решение №3)
  ├─ (3) Каталог: inline-кнопки активных продуктов (как сейчас, _catalog_kb)
  ├─ (4) Открытие продукта (cb prod:{id}) → ПРЕЗЕНТАЦИЯ:
  │        for block in product.content_blocks (order_idx):
  │            send_chat_action(typing|record_video_note|record_voice|upload_photo)
  │            sleep(delay_ms)
  │            send block (text / media / media_group / video_note / voice)
  │        затем — карточка с ценами (card_text) + inline:
  │            [📝 Оставить заявку]  [‹ К каталогу]
  ├─ (5) Заявка (cb lead:{id}) — как сейчас (+ опц. форма), фиксируется горячий лид по продукту
  └─ (6) После покупки (grant_for_payment) → thank_you_message продукта
```

Реализация «живости»: хелпер `bot/sender.py::send_presentation(bot, chat_id, product)` —
последовательно шлёт блоки с `bot.send_chat_action(...)` и `asyncio.sleep(delay_ms/1000)`
(кружок → `record_video_note`, голос → `record_voice`, фото → `upload_photo`, текст → `typing`).

Глубинная ссылка `/start <slug>` может вести сразу к презентации конкретного продукта
(трекинг-ссылка с product_id → сразу шаг 4) — для горячего трафика «в лоб» на оффер.

Кнопки/гейтинг по фичам: всё под существующими фичефлагами (catalog/leads — ядро).

## 5. Отправитель медиа (рефактор + расширение)

Вынести из `workers/scheduled_messages.py` общий модуль **`bot/sender.py`**:
- `send_media_item(bot, chat_id, media, caption, reply_markup)` — по media_type:
  photo/video/animation/audio/document/voice/**video_note** (для voice → `send_voice`,
  для video_note → `send_video_note`, без caption — у кружка/голоса подпись Telegram не поддерживает,
  текст шлём отдельным блоком).
- `send_media_group(bot, chat_id, items)` — альбом (фото/видео), как сейчас.
- retry по «bad file_id», кэш telegram_file_id (как в текущем коде).
- worker воронок начинает использовать этот же `bot/sender.py` (DRY).

Нюансы video_note: квадрат, ≤60с, без подписи; если загруженное видео не квадрат — Telegram
обрежет/может отклонить. В админке предупредить про требования к кружку.

## 7. Заявки и горячие лиды

- Кнопка «📝 Оставить заявку» на карточке (есть) → лид с `product_id` (горячий лид по продукту).
- Опционально перед заявкой — мини-форма (reuse forms) или сразу лид (one-tap) — Решение №4.
- Лид виден в админке (раздел «Заявки», фильтр по продукту), далее менеджер ведёт к оплате
  (платёж с обязательным чеком — уже реализовано).
- Презентация повышает «температуру»: смотрел кружок/видео → выше конверсия в заявку.

## 9. Риски / нюансы

1. **Кружок (video_note):** строгие требования (квадрат, ≤60с, без подписи). Подсказки в админке;
   текст к кружку — отдельным блоком. Возможна предобработка (ffmpeg-кроп) — вне MVP.
2. **Размеры/скорость:** видео крупные → отправка занимает время; chat_action закрывает «паузу».
   Кэш `telegram_file_id` критичен (не перезаливать на каждого юзера).
3. **`parse_mode=HTML`** для card_text/thank_you/text-блоков; экранирование пользовательского текста
   не требуется (это контент менеджера), но валидировать на «битый HTML» при сохранении.
4. **Громкость презентации:** не перегружать — рекомендация в UI «3–5 блоков». One CTA в конце.
5. **Идемпотентность:** повторное открытие продукта шлёт презентацию заново — ок (по запросу).
   Анти-спам: дебаунс на быстрые повторные клики `prod:{id}`.
6. **Фичефлаги:** каталог/заявки — ядро; презентация продукта — часть каталога (всегда), но
   можно завести флаг `product_presentation` при желании.
7. **Хранилище:** `product_media` на том же volume `/var/lib/infobizbot/product_media` (как step_media/receipts).
