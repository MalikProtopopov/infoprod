# UX-предложение: «Студия воронки» (v2, после ревью)

> **Версия 2.0**, интегрирует ревью продакт-дизайнера: primary+secondary точки входа, превью TG в P0, отдельный раздел про mobile, observable test, safety при правке активных воронок, empty states зависимостей, заглушка под A/B.
>
> **Проблема**: чтобы запустить одну воронку, владельцу нужно пройти 5 страниц в правильном порядке. Каждый раз он теряет контекст. Если забыл подключить точку входа — воронка не запустится, и об этом нигде не написано.
>
> **Цель**: одна **«Студия воронки»** где делается всё, плюс menager'ы ресурсов (`/lead-magnets`, `/funnel-triggers`) для опытных юзеров.

---

## 1. Текущее состояние (baseline)

5 разных контекстов. Зависимости неочевидны. Прогресс нигде не виден.

```
┌─ Лидмагниты ──┐    ┌─ Воронка ──┐    ┌─ Шаги ────┐    ┌─ Точки входа ──┐
│ Загрузить PDF │ → │ Имя+TTL    │ → │ Текст+    │ → │ Ссылка ИЛИ      │
│ (заранее!)    │    │ +продукт   │    │ лидмагнит │    │ Слово ИЛИ       │
└───────────────┘    └────────────┘    │ ×N штук   │    │ default product │
                                       └───────────┘    └─────────────────┘
       ↑                    ↑                 ↑                    │
       └─ если забыл —     │                  │              разные страницы
         возвращайся       │                  │              для разных типов
                          возвращайся         │
                  чтобы default_funnel поставить
```

## 2. Главный принцип

> Одна **«Студия воронки»** = всё для запуска. `/lead-magnets` и `/funnel-triggers` остаются как **«библиотеки ресурсов»** для опытных юзеров.

## 5. Observable Test Panel (вместо closed box)

**Большое улучшение в v2**: «Тест на меня» — это не просто кнопка → ждать. Это **наблюдаемая панель** где видно процесс.

При клике [▶ Тест на меня] — справа появляется панель (или поверх §4 expand):

```
┌─ Тестовая воронка запущена ──────────────────── [×] ────────────────┐
│                                                                       │
│ Все шаги уменьшены в 60 раз: «1 день» = 24 секунды, «1 час» = 1 мин. │
│                                                                       │
│ ┌─ Прогресс ────────────────────────────────────────────────────┐   │
│ │ ✅ Шаг 1 «Welcome + чек-лист»                                  │   │
│ │     Отправлен 12 секунд назад                                  │   │
│ │     ✓ Текст доставлен                                          │   │
│ │     ✓ Лидмагнит "7 шагов утреннего ухода" доставлен            │   │
│ │                                                                 │   │
│ │ ⏳ Шаг 2 «Кейс пациентки»                                      │   │
│ │     Отправится через 12 секунд (вместо 1 дня)                  │   │
│ │     ●●●●●●○○○○○○○○                                            │   │
│ │                                                                 │   │
│ │ ○  Шаг 3 «4 типичные ошибки»                                   │   │
│ │     Отправится через 60 секунд (вместо 3 дней)                 │   │
│ │                                                                 │   │
│ │ ○  Шаг 4 «Соц-доказательство»                                  │   │
│ │     Отправится через 1 мин 40 сек (вместо 5 дней)              │   │
│ │                                                                 │   │
│ │ ○  Шаг 5 «Финальное приглашение»                               │   │
│ │     Отправится через 2 мин 20 сек (вместо 7 дней)              │   │
│ └─────────────────────────────────────────────────────────────────┘   │
│                                                                       │
│ [📱 Открыть Telegram]      [⏸ Прервать тест]                         │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```

**Что в панели**:
- Список всех шагов с реальными relative-таймштампами
- ✅ = отправлен (с подтверждением что лидмагнит тоже доставился)
- ⏳ = текущий ожидающий — с прогресс-баром
- ○ = ещё не отправлен
- Дублирование времени в формате «X секунд назад / X секунд осталось» — юзер сразу понимает скорость
- Кнопка «Открыть Telegram» — `tg://` deep-link сразу в бота
- «Прервать тест» — отменяет недотправленные шаги

Это снимает страх «я нажал — ничего не происходит». Юзер видит процесс и доверяет ему.

## 6. Safety при правке активных воронок (НОВЫЙ раздел)

**Сценарий**: воронка активна, 47 пользователей в ней. Юзер открывает шаг 3, меняет текст. Что теперь?

Без защиты — изменения коснутся всех 47, кто ещё не получил шаг 3. Может быть это OK (исправление опечатки), может — катастрофа (поменяли price-anchor).

### 6.4 Undo-stack для критичных правок

Для P2: после сохранения активной правки — в углу появляется toast «Изменения применены. [Отменить — 30 сек]». Это последняя страховка.

## 9. Wizard → Студия (seamless transition)

После завершения wizard'а — юзер попадает в студию. Без подсветки cognitively шок: «я только что заполнял 4 экрана — где они теперь?».

### 9.1 Решение — pulse-highlight подходящих секций

При первом раскрытии студии после wizard'а каждая заполненная секция мигает мягким indigo-300/40 pulse'ом 2-3 секунды, по очереди сверху вниз:

```
0.0s — §1 Параметры pulse 1s (видит что параметры заполнились)
1.5s — §2 Шаги pulse 1s (видит "вот 5 шагов которые wizard создал")
3.0s — §3 Точки входа pulse 1s + ❗-индикатор привлекает внимание
4.0s — §4 Запуск pulse 1s
```

После — спокойный обычный режим.

### 9.2 Альтернатива — overlay-tour первый раз

Если pulse не хватает, можно добавить **product-tour** (как в Intercom Product Tours) — 3-4 tooltip'а с next-кнопкой:

```
┌──────────────────────┐
│ ① Тут параметры      │
│   вашей воронки      │
│           [Дальше →] │
└────┬─────────────────┘
     │
     ▼
   §1 Параметры
```

Показывается только первый раз. Можно skip.

### 9.3 Если wizard был пропущен (опытный)

Юзер нажал «Создать пустую» в любой момент — попадает в студию **без** pulse-highlights и без тура. Это чистый experience для тех, кто уже знает.

## 10. A/B-тестирование — заглушка под фичу (НОВЫЙ раздел)

Для продающих воронок A/B-тест шага — базовая фича на 6-12 месяце. Backend ещё не делает, но место под фичу должно быть в UI с самого начала. Иначе через год придётся переделывать всю студию.

### 10.1 Кнопка «Создать вариант B» в редакторе шага

```
┌─ Редактор шага 2 «Кейс пациентки» ─────────────────────┐
│ [Вариант A]  [+ Создать вариант B]                     │
│ ─────────                                              │
│                                                         │
│ Задержка: 1 день, Активен: ✓                          │
│                                                         │
│ Текст: ...                                             │
└─────────────────────────────────────────────────────────┘
```

Когда нажимаешь «+ Создать вариант B»:

```
┌─ A/B-тест шага 2 ────────────────────── coming soon ───┐
│                                                         │
│ ⏳ Эта фича будет доступна в следующих версиях.         │
│                                                         │
│ С её помощью можно будет:                              │
│ • Создать вариант B текста этого шага                  │
│ • Распределить трафик 50/50 (или другой split)         │
│ • Сравнить open-rate, click-rate, конверсию в paid     │
│                                                         │
│ Нужна сейчас? Напишите фидбек:                         │
│ [Хочу A/B-тестирование]                                │
└─────────────────────────────────────────────────────────┘
```

Кнопка «Хочу A/B-тестирование» собирает feedback (POST /api/feature-requests или просто email). Это даёт **product signal** «как часто эта фича нужна» и **держит место в UI** так что когда мы её сделаем — юзер не удивится.

### 10.2 Если фича на готова — placeholder в виде tab'а

В редакторе шага сверху может быть таб-bar:

```
┌─ [Вариант A] [Вариант B 🔒] ───────────────────────────┐
│                                                         │
│ (контент шага)                                         │
└─────────────────────────────────────────────────────────┘
```

Замочек 🔒 показывает «закрытая фича». Tap по нему — то же CTA окно.

## 14. Технические заметки для реализации

- **Backend не меняется** — все эндпоинты есть.
- Опционально 1 новый: `GET /api/funnels/{id}/entry-points` агрегирует `{tracking_links[], triggers[], is_product_default}` за 1 запрос. Можно делать 3 параллельных GET'а на клиенте, но 1 endpoint cleaner.
- Опционально 2 новый: `POST /api/funnels/{id}/test-run` — создаёт временную FunnelEntry для текущего admin'а с `delay_minutes / 60`. Через TTL=10мин — auto-cleanup. Используется для §4 Тест.
- Опционально 3 новый: `POST /api/feature-requests` для CTA «Хочу A/B-тестирование» — собирает product feedback.
- **Wizard и студия** — одна страница `/funnels/{id}/edit` в режиме «новая воронка». Wizard поверх студии, после завершения растворяется + pulse-highlights.
- **Анкор-навигация**: `#section-1`, `#section-2`, etc. — для smooth-scroll кликов в прогресс-баре.
- **`is_active` flag** — уже есть в Funnel. Семантика «draft» = `is_active = false`.
- **`active_entries` count** — уже возвращается из `/api/funnels` GET. Используется для safety-warning.

## 15. Сравнение «было/станет» для юзера

### Сценарий: «Настроить воронку прогрева под Instagram-пост о клубе»

**Сейчас** (`6 переходов между страницами`):
1. Открываю `/lead-magnets`, загружаю PDF чек-листа
2. Перехожу в `/funnels`, создаю воронку, выбираю продукт
3. Попадаю в редактор, добавляю 5 шагов, привязываю PDF к первому
4. Возвращаюсь в `/products`, нажимаю «Изм.» на клуб, выставляю default_funnel
5. Иду в `/products/{id}`, создаю tracking_link с указанием funnel
6. Копирую URL, иду в Instagram
7. Опц.: иду в `/funnel-triggers`, добавляю слово КЛУБ

**Станет** (`1 переход + всё в студии`):
1. Открываю `/funnels`, нажимаю «+ Создать», выбираю продукт + шаблон 5-шагов (wizard 4 экрана)
2. В студии:
   - §1: уже заполнено wizard'ом (pulse-highlight 1 сек)
   - §2: правлю текст шагов, к первому жму «+ Загрузить лидмагнит» — модалка с dropzone, выбираю PDF. Превью TG справа сразу показывает как будет
   - §3: на primary-карточке Trackable Link жму «+ Новая ссылка», заполняю utm — копирую URL
