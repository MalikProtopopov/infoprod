# Infobizbot Admin — UI/UX audit для дизайнера

> Снимок текущего состояния админ-панели. Покрывает: используемый design system, реализацию ключевых страниц (особенно конструктора воронок), UX-паттерны, что работает и что можно улучшить.
>
> Цель — дать дизайнеру полное представление об интерфейсе без необходимости лезть в код, чтобы можно было либо подсветить пробелы, либо предложить редизайн отдельных экранов.

---

## 1. Обзор системы

**Стек**: Next.js 15 (App Router) + React 19 + TypeScript + Tailwind CSS 3 + SWR для данных.

**Шрифт**: Inter (Google Fonts), вкл. `'cv11', 'ss01', 'ss03'` фичи для красивых цифр и одинарной кавычки `'`.

**Палитра** (`globals.css`):

| Назначение | Цвет |
|---|---|
| `--ink` | `#0b1020` (почти-чёрный, основной текст) |
| `--ink-2` | `#2a2f45` (вторичный текст) |
| `--muted` | `#6b7280` (плейсхолдеры) |
| **Accent (primary)** | indigo-500 → violet-500 → fuchsia (gradient) |
| **Danger** | rose-500 → pink-700 |
| **Teal** | `#14b8a6` (фон-блоб) |

**Фон страницы** — статичный, не скроллится:
```css
radial-gradient(1200px 800px at -10% -10%, rgba(99,102,241,0.18))   /* indigo сверху-слева */
+ radial-gradient(900px 700px at 110% 10%, rgba(244,114,182,0.16))  /* rose сверху-справа */
+ radial-gradient(900px 700px at 50% 120%, rgba(20,184,166,0.12))   /* teal снизу */
+ linear-gradient(#f8faff → #f4f6fb)                                 /* базовый */
```

Поверх плавно анимируются 3 «блоба» (см. `.anim-blob-1/2/3`) — медленное движение 18-26 секунд, создаёт ощущение «живого» фона.

### Главная идея — **Glassmorphism**

Три уровня прозрачных «стёклышек»:

| Класс | Прозрачность | Когда | Box-shadow |
|---|---|---|---|
| `.glass` | 65% | Обычные карточки, sidebar background | `0 10px 30px -12px rgba(15,23,42,0.18)` + inset highlight |
| `.glass-strong` | 85% | Sidebar (полностью), drawer/sheet | `0 24px 50px -18px rgba(15,23,42,0.25)` |
| `.glass-soft` | 55% | Ghost-кнопки, мягкие фоны | мягче, без shadow |

Все три с `backdrop-filter: blur(14-20px)` + `saturate(150-180%)`. На фоне с цветными блобами это даёт красивый эффект — карточки слегка тонируются цветом подложки за ними.

## 2. Component inventory (`components/ui.tsx`)

Все building blocks в одном файле, **308 строк**, без зависимостей от внешних UI-библиотек (только Tailwind + clsx).

### 2.1 Кнопки

```tsx
<Button variant="primary" size="md">Создать</Button>
<Button variant="ghost">Отмена</Button>
<Button variant="danger">Удалить</Button>
<Button variant="glass">Скачать QR</Button>
```

| Variant | Look | Когда |
|---|---|---|
| `primary` | Градиент indigo→violet→fuchsia, белый текст, тень-svetlow в indigo | CTA, главное действие в форме |
| `ghost` | `glass-soft` фон, тёмный текст | Вторичные действия, табы |
| `danger` | Градиент rose→pink, белый текст | Деструктив (удаление) |
| `glass` | Простое стекло, без градиента | Нейтральные (скачать, копировать) |

Размеры: `sm` (h-8, text-xs) / `md` (h-10, text-sm) / `lg` (h-12, text-base).

Микро-эффект на active: `translate-y-px` — кнопка «нажимается» вниз.

### 2.2 Inputs

Все используют единый `INPUT_CLASS`: белый фон 85%, blur, мягкая граница, focus-state — indigo-300 ring.

- **`<Input>`** — высота 40px (h-10), border-radius 12px (rounded-xl).
- **`<Textarea>`** — paddings 14×10px, тот же стиль.
- **`<Select>`** — то же + appearance-none (но кастомного chevron-icon нет — это **слабое место**).
- **`<Field label hint required>`** — обёртка с label сверху (uppercase 11px) и хинтом снизу (11px gray).

### 2.3 Cards

```tsx
<Card padded className="anim-rise">Контент</Card>
<PlainCard>Без glass-эффекта, обычный белый</PlainCard>
```

`<Card>` — это `<div>` с `.glass` + `rounded-2xl`. `padded` добавляет 20-24px паддинг.

### 2.4 Pill (значки-чипы)

```tsx
<Pill color="green">активна</Pill>
<Pill color="indigo">5</Pill>
```

8 цветов: `indigo / violet / green / amber / red/rose / gray / sky`. Каждый — пастельный фон 80%, цветной текст, тонкая ring-граница.

### 2.5 Sheet (drawer справа)

Самый важный паттерн модальных диалогов. Slide-in справа, максимальная ширина 480px (size=lg → 640px).

```tsx
<Sheet
  open={open}
  onClose={() => setOpen(false)}
  title="Загрузить лидмагнит"
  description="PDF, изображение, видео — до 50 МБ"
  footer={<><Button variant="ghost">Отмена</Button><Button>Загрузить</Button></>}
>
  {/* form content */}
</Sheet>
```

Структура:
- Тёмный backdrop с blur (rgba(15,23,42,0.3))
- Панель glass-strong
- Header: заголовок 18px-bold + опц. description 12px-gray + кнопка ✕
- Scrollable body
- Footer: фиксированные действия (отмена/сохранить)

ESC закрывает. body-scroll блокируется пока открыт.

### 2.6 PageHeader, Empty, Stat, TableHead/Th/Tr/Td, IconButton

Базовая обвязка — стандартные паттерны. `<Stat>` — карточка с большой цифрой (`text-3xl font-bold`) для дашборда. Поддерживает 5 акцентов через градиентную «плашку» с иконкой справа.

**Sidebar — 260px ширина, sticky top: 3** (отступ от верха) + `glass-strong`.

Активный пункт меню подсвечивается:
- Белый фон 85% + `shadow-soft`
- Слева — 3px градиентный «маркер» (indigo→violet→fuchsia), `rounded-r-full`

- Текст становится тёмно-чёрным (text-ink)

При `< 640px` (sm:):
- Sidebar становится `fixed inset-y-0 left-0` overlay, скрывается за `-translate-x-full`

- Tap на пункт меню — sidebar закрывается (`navOpen → false` в useEffect)
- Backdrop при открытом меню — `bg-slate-900/30 backdrop-blur-[2px]`

### 3.3 Breadcrumbs

Простая текстовая навигация: `Обзор / Воронки / Редактировать`. Активный элемент жирный + тёмный, предыдущие — серые ссылки.

### 3.4 Topbar

Высота 56px (h-14), glass-фон. Содержит:
- (mobile only) кнопка «бургер»
- Breadcrumbs (слева)
- (desktop only) shortcut «Заявки» с иконкой
- Карточка пользователя: аватар-инициал + username

4. Пользователи (`/users`)

Сейчас группировки нет — есть только поле `group?` в `NAV`-конфиге, но визуально не использовано.

### 4.2 Что хорошо

1. **Двухколоночный layout** — слева список шагов, справа редактор. На больших экранах удобно: видишь контекст и редактируешь одновременно.

2. **Drag&drop переупорядочивание** — реализован через native HTML5 `draggable` API (`onDragStart`/`onDragOver`/`onDrop`). Сразу после drop — POST `/api/funnels/{id}/reorder`. Активный (редактируемый) шаг имеет ring-2 ring-indigo-400.

3. **Удобная задержка через 3 поля**: число + unit-селект (минуты/часы/дни) + чекбокс «активен». Хранится в БД в минутах, на UI автоматически детектится самая большая удобная единица (1440 мин → «1 день»). Это лучше чем единое поле минут.

4. **Текст шага** — обычный `<Textarea>` 8 строк. Поддерживает HTML и плейсхолдеры `{first_name}` / `{username}`.

5. **Hint про лидмагнит**: «Файл отправится отдельным сообщением после текста» — пользователю сразу понятно поведение.

6. **Счётчик символов** внизу — `145 симв.`. Без жёсткого лимита, но визуально помогает.

7. **Карточка шага в списке** показывает превью текста (первые 60 символов + …), задержку в человеческом виде, маркер лидмагнита, статус отключения.

### 4.3 Слабые места (для дизайнера)

> **Открытые UX-проблемы, которые стоит решить редизайном.**

1. **Нет визуального превью Telegram-сообщения.** Сейчас текст шага редактируется как plain text. Дизайнеру стоит добавить *режим превью* справа от текста — как будет выглядеть в Telegram-чате с HTML-форматированием, аватаркой бота, отступами. В ТЗ это описано как «имитация чата Telegram» внизу страницы — **не реализовано**.

2. **Кнопки шага редактируются как JSON.** Поле `buttons` в `funnel_steps` — это `jsonb`. На UI **редактора кнопок нет вообще** — поле просто сохраняется как `null`. ТЗ говорит «визуальный редактор inline-кнопок» — нужен. Минимум: добавление кнопки [текст | callback_data | url].

3. **Drag&drop без визуальной обратной связи.** Когда тащишь шаг — не видно куда он упадёт (нет ghost-плейсхолдера, нет линии-индикатора). Только курсор меняется на grab/grabbing.

4. **Нет sticky-кнопки «Сохранить шаг».** При длинном тексте сообщения CTA уезжает вниз страницы. Решение: footer-bar с CTA, не скроллящийся.

5. **Нет undo.** Если случайно удалил шаг — нужно полностью перенабирать. Хотя бы toast «Шаг удалён [Восстановить]» на 5 секунд.

6. **Лидмагнит — только селект.** Нет ни inline-просмотра, ни кнопки «загрузить новый прямо отсюда». Если нужного файла нет — приходится уходить на `/lead-magnets`, загружать, возвращаться. **Должна быть** кнопка «+ Новый лидмагнит» рядом с селектом, открывающая Sheet поверх.

7. **Нет «Тестовый запуск на меня»** из ТЗ (раздел 11.5) — кнопка, которая создаёт FunnelEntry для админа со скоростью x60 (минуты становятся секундами). Сейчас нельзя проверить воронку быстро.

8. **Параметры воронки на ввод реагируют только по кнопке «Сохранить».** Нет auto-save / nodirty-индикатора. Если ввёл TTL=14 и забыл нажать — изменения теряются. Дизайнеру стоит решить: explicit save (как сейчас, но с warning при уходе) или debounced auto-save.

9. **Метаданные воронки и шаги — раздельная навигация.** Сохранение мета не подсвечивает дальше редактируемый шаг. Логически они связаны, но визуально — две независимых формы.

10. **Нет инфо-блока про текущую конверсию воронки.** В list-странице показывается `active_entries` / `completed_entries`, но при редактировании этой статистики не видно. Если воронка работает плохо — где это увидеть? Нужен либо широкий header с метриками (как у YouTube Studio), либо отдельная вкладка `/funnels/[id]/stats`.

11. **Нет навигации между шагами клавиатурой.** Только мышь. Стрелки вверх-вниз — на список шагов, Tab — на следующее поле редактора.

12. **Лидмагниты-селект показывает все.** Нет фильтра по продукту воронки. Если их много — придётся листать.

## 5. Другие страницы воронок

### 5.1 `/funnels` — список

| Колонка | Что |
|---|---|
| Название | `<Link>` на edit + описание серым ниже |
| Шагов | `<Pill color="indigo">5</Pill>` |
| Активных | `<Pill color="green">12</Pill>` |
| Завершено | Цифра без pill |
| TTL | `90 дн.` |
| Auto-cancel | `<Pill violet>да</Pill>` |
| Статус | activна / выключена |
| Действия | [Редакт.] [Подписчики] [Удалить-danger] |

CTA сверху-справа: **+ Создать воронку**. Открывает Sheet с минимальным набором полей (имя, продукт-селект, TTL, cancel_on_payment). После создания — редирект на `/funnels/{id}/edit`.

**Слабое место**: после создания воронки нельзя удобно перепрыгнуть на список шагов. Sheet → редирект — это правильно, но было бы хорошо ещё показать toast «Создано. Добавьте первый шаг ↓».

### 5.2 `/funnels/[id]/entries` — подписчики

Таблица с вкладками наверху: `Активные / Завершено / Отменено / Все`. Каждая запись:
- Колонка «Пользователь» — аватар-инициал в градиентном круге + имя/username, ссылка на `/users/{id}`
- «Источник» — pill в зависимости от типа (Ссылка / Слово / Заявка / Вручную)
- «Старт» — `dd.mm.yyyy hh:mm`
- «Статус» — pill (активна/завершена/отменена)
- «Причина отмены» — серый текст (если есть)
- «Действия» — только для active: кнопка `Отменить` (danger)

**Хорошо**: вкладки + pills делают сканирование легким. **Слабое место**: нет фильтра по дате, поиска по имени пользователя.

### 5.3 `/lead-magnets` — список + upload

Sheet «Загрузить лидмагнит» имеет **dropzone** с drag&drop файла:
- Большая зона `border-2 border-dashed`, при drag-over подсвечивается indigo
- Иконка 📤 + текст «Перетащите файл сюда или кликните»
- После выбора — превью с типовой иконкой (📄 PDF, 🖼️ image, 🎬 video, 📎 other), именем файла, размером
- Дальше — поля «Название» (авто-заполняется из имени файла), «Описание», «Привязка к продукту»

В таблице:
- Колонка «Файл» с эмодзи + название + описание
- «Тип» (`PDF`/`IMAGE`/`VIDEO` uppercase)
- «Размер» (KB/MB)
- «Продукт» (название или `<span class="text-zinc-400">универсальный</span>`)
- «Загрузок» (Pill violet, если >0)
- «TG cache» — `<Pill green>кеш</Pill>` если `telegram_file_id` уже сохранён (после первой отправки)
- Кнопки: Скачать (ссылка на `/api/lead-magnets/{id}/download`) / Выключить/Включить / Удалить

**Сильно**: dropzone, эмодзи типов, TG cache индикатор. **Слабо**: нет превью (для PDF — первая страница, для видео — кадр). В ТЗ описано — не реализовано.

### 5.4 `/funnel-triggers` — кодовые слова

Простейшая CRUD-страница:
- Колонка «Слово» — `<code>` в светло-серой плашке
- «Воронка» — ссылка на edit
- «Использовано» — счётчик через pill
- «Статус» — активен/выключен
- Кнопки Включить/Выключить + Удалить

Sheet создания: ввести слово (placeholder «старт»), выбрать воронку из dropdown. Hint: «Например: КЛУБ, ОБУЧЕНИЕ, СТАРТ. Регистр не важен — система сохраняет в нижнем».

API при duplicate возвращает 409 — UI показывает inline-error в rose-боксе под формой.

## 6. Общие UX-паттерны / конвенции

### 6.1 Подтверждения удаления
Везде через `confirm()` нативный браузерный диалог: `Удалить продукт «Yoga Pro»?`. **Слабое место**: native `confirm` нельзя стилизовать, выглядит чужеродно на фоне glassmorphism. Стоит реализовать `<ConfirmDialog>` через Sheet или отдельный модал.

### 6.2 Ошибки API
В формах внутри Sheet — inline-блок:
```
text-sm text-rose-600 bg-rose-50/80 border border-rose-200/60 rounded-xl px-3 py-2
```

Например: `"Слово 'старт' уже используется"`. На list-страницах — `alert()` (тоже нативный).

### 6.3 Loading states
- На уровне страницы: `<div className="p-6 text-sm text-zinc-500">Загрузка…</div>` или скелетоны для дашборда (4 серых `animate-pulse` карточки)
- На уровне кнопки: `disabled={busy}` + текст «Создаём…» вместо «Создать»

### 6.4 Animations

Только 4 кастомных:
- `anim-rise` — fade + slide-up 8px (380ms cubic-bezier) — карточки при загрузке
- `anim-fade` — opacity 0→1 (240ms) — backdrop
- `anim-slide-right` — slide справа (320ms) — Sheet
- `anim-blob-1/2/3` — медленное движение фоновых blob (18-26s loop)

Микро-интеракции:
- Button active: `translate-y-px`
- Link active в sidebar: 3px градиент-маркер слева

### 6.5 Pillage scheme (когда какой цвет)

| Цвет | Семантика | Примеры |
|---|---|---|
| **green** | Успешно, активно, положительно | active subscription, payment-paid, активен |
| **red/rose** | Ошибка, отмена, опасно | cancelled, danger button |
| **amber** | Внимание, новое | новая заявка, expiring soon |
| **indigo** | Главный акцент, метрика | активные шаги, ссылка |
| **violet** | Вторичный акцент | лидмагнит, кодовое слово, download_count |
| **gray** | Нейтральное, выключено | inactive, unknown source |
| **sky** | Информационное | (редко) |

## 7. Что точно стоит решить дизайнеру (топ-10)

1. **Конструктор воронок: визуальное превью Telegram-сообщения** → расширить редактор шага, добавить imitation chat-bubble.
2. **Конструктор воронок: визуальный редактор inline-кнопок** → drag&drop рядов кнопок, выбор типа (callback / URL).
3. **Конструктор воронок: «Тестовый запуск на меня x60»** → кнопка вверху страницы.
4. **Подсветка drop-target** при drag&drop шагов.
5. **Сгруппировать sidebar на 4-5 секций** — 12 плоских пунктов это много.
6. **Custom confirm-dialog** вместо нативного `confirm()` — серьёзный hit по premium-ощущению.
7. **Custom select chevron** — сейчас appearance-none без альтернативной стрелки, в Firefox/Safari ничего не показывает.
8. **Кнопка «+Новый лидмагнит»** прямо в редакторе шага.
9. **Превью PDF/видео** на странице лидмагнитов.
10. **Inline-метрики у редактора воронки** — конверсия, активных подписчиков, чтобы редактор был «осознанным».

## 8. Технический долг для дизайнера

- **Нет токенов дизайн-системы** (Figma tokens / Style Dictionary). Цвета захардкожены в classNames, gradient'ы — в CSS. Если переименовать `--ink` → нужно перепроверить весь код.
- **Иконки — inline SVG** в `layout.tsx` (объект `I`). Не вынесены в файлы, не используется icon-library. При редизайне иконок придётся править несколько мест.
- **Нет dark mode** — `color-scheme: light` зашит. Все цвета привязаны к светлой теме.
- **Нет responsive-варианта Sheet** для очень узких экранов (< 360px) — горизонтальный overflow возможен.
- **Custom focus-ring** разный в разных местах: где-то 2px indigo-400/60 (Button), где-то 2px indigo-300/40 (Input).

## 10. Контекст для понимания продукта

**Infobizbot** — B2B SaaS для инфобизнеса: продаёт доступ в закрытые Telegram-каналы. Админка нужна владельцу инфопродукта (например, врачу-косметологу Заза Мамаевой из ТЗ) для:

- Управления каналами и продуктами
- Сбора заявок от подписчиков
- Фиксации оплат → автоматического выдачи invite-ссылок
- Аналитики источников трафика (UTM, конверсии)
- **Воронок прогрева** — серий follow-up сообщений с лидмагнитами, прерываемых при оплате

Целевая аудитория админки — **не разработчики**, а маркетологи/SMM-специалисты эксперта. Поэтому UI должен быть:
- понятным без обучения
- быстрым в основных сценариях (создать ссылку — 30 секунд)
- безопасным от случайных деструктивных действий

Текущая реализация **функционально полная** (все CRUD работают, deploy на проде), но **UX-полировка** (особенно конструктор воронок) — точка роста для премиум-ощущения.
