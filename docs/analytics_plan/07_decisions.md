# 07. Решения по открытым вопросам

Решения зафиксированы в ТЗ §12 и реплицированы здесь для удобства. Любые отклонения от них при реализации должны быть согласованы.

| # | Вопрос | Решение | Обоснование |
|---|--------|---------|-------------|
| 7.1 | QR-коды — на бэке или на фронте? | **Бэкенд**, `python-qrcode + Pillow`, эндпоинт `GET /api/tracking-links/{id}/qr.png` | Универсально: можно открыть прямую ссылку, поделиться, использовать в офлайн-материалах |
| 7.2 | Разрешать кастомный slug? | **Да**, за «Расширенные настройки» | Полезно для шеринга (`yogasale` > `kx9p3a`). Валидируется уникальностью и форматом |
| 7.3 | Атрибуция, когда TTL истёк или ссылки не было | **Не наследовать UTM из first-touch user** | Чистое разделение first-touch (на user) и last-touch (на lead). В отчётах «органика» = NULL utm_source |
| 7.4 | Удаление пользователя — что с tracking_link counters? | Пока нет API удаления — отложено. При появлении: `click_count`, `unique_users` **не пересчитываются** | Не изменять историю |
| 7.5 | Events-таблица сразу? | **Нет, Phase 4** | Все отчёты Phase 1–3 строятся поверх существующих таблиц JOIN-ами. Events нужны для micro-conversions, что не выводится из текущей схемы |
| 7.6 | Мульти-ботовая атрибуция — дедупликация users по `telegram_user_id`? | Откладывается до появления второго бота | Сейчас один TG user = одна запись `users`; при появлении мульти-бот логики решать отдельно |

## Дополнительные решения, принятые на этапе планирования

| # | Вопрос | Решение |
|---|--------|---------|
| extra.1 | Slug + product.code общий namespace | Да. Validator на обоих создающих эндпоинтах |
| extra.2 | Длина slug | 8 символов по умолчанию, 4–64 — допустимый диапазон для custom |
| extra.3 | Символы slug | `[A-Za-z0-9_-]` (буквы, цифры, `_`, `-`). Длина 8 при 62 алфавите → 62^8 ≈ 2×10^14 комбинаций |
| extra.4 | Что делать если за 10 попыток не сгенерили уникальный? | Raise `GenerationError`, API возвращает 500. На текущем масштабе невозможно |
| extra.5 | Где валидировать формат slug | И в Pydantic (`pattern`), и в БД (`CHECK constraint`), и в сервисе (`re.match`). Тройная защита |
| extra.6 | Hard-delete tracking_link | Только если нет связанных leads и payments. Иначе 409 |
| extra.7 | UTM-поля в lead/payment | Снапшот при создании. **Изменить нельзя** (даже через API) — для целостности атрибуции |
| extra.8 | Изменение UTM существующей tracking_link | Запрещено в PATCH-эндпоинте. Можно только `notes` и `is_active`. Если нужны новые UTM — создавать новую ссылку |
| extra.9 | Где хранится текущая ссылка пользователя | В `users.current_tracking_link_id` + `current_link_set_at`. Без Redis, без отдельной таблицы сессий |
| extra.10 | Когорта пользователя для retention | Месяц `first_seen_at`. Для quarterly когорт — изменить grouping в SQL |
| extra.11 | Тайм-зона расчётов | UTC (как и весь проект) |
| extra.12 | Pagination в `/api/stats/sources` | На Phase 1 — нет, потому что строк мало (по числу источников). При >100 источников — добавить |
| extra.13 | Кеширование агрегатов | Не делаем на Phase 1–3. Эндпоинты считают on-the-fly. При нагрузке — materialized views с REFRESH по cron |

## Решения, требующие согласования при появлении

Это якорные точки — если возникает один из этих сценариев, остановиться и решить с заказчиком:

- **Появление второго активного бота** → дедупликация `users.telegram_user_id` между ботами или сохранение разделения?
- **Запрос «хочу атрибуцию на конкретный пост в TG-канале»** → потребуется доменная модель `traffic_sources` с более тонкой структурой
- **Запрос «хочу видеть, сколько user'ов вернулись после первой сессии без покупки»** → нужны events (Phase 4)
- **Запрос «хочу A/B-тесты двух CTA в карточке»** → нужны events + dimension `variant`
- **Запрос «хочу платить % менеджеру с продажи»** → нужен `payments.admin_id` (миграция уже есть), плюс UI с фильтром по менеджеру

## Версионирование решений

При значимых изменениях этих решений — обновлять этот файл с пометкой даты. Например:
```
### Изменено 2026-09-01: TTL контекста ссылки увеличен с 30 минут до 24 часов
Причина: жалобы что клиенты «думают день» и теряют атрибуцию.
Решение: изменить константу в боте на 24h.
```
