# Grammy — инструкция по настройке воронки

> Этот файл — **подробное руководство для AI-ассистента** (или человека),
> который готовит и запускает воронку в админ-панели Grammy
> (`grammy.mediann.dev`). Здесь описаны все поля, форматы, лимиты,
> доступные действия и типичные шаблоны.

---

## 0. Что такое Grammy в одной фразе

Платформа управления Telegram-ботом и закрытыми каналами:
**бот ловит заявки → менеджер фиксирует оплаты → бот сам выдаёт доступ в
канал и сам отзывает по истечении подписки**. Воронка — это серия
отложенных сообщений, которая греет клиента и предлагает действия
(заявка / тарифы / другая воронка / ссылка).

---

## 1. Подготовка: что должно быть до запуска воронки

Воронка не существует в вакууме — она опирается на три сущности
**в каталоге**:

### 1.1 Бот (Bot)
Раздел: **Каталог → Боты**

| Поле | Что вводить |
|---|---|
| token | Скопировать у `@BotFather` после `/newbot` |

После сохранения система через `getMe` подтянет `username` и `title`
автоматически. Один бот может обслуживать **несколько каналов и
продуктов** — отдельный бот на каждый продукт не нужен.

### 1.2 Канал (Channel)
Раздел: **Каталог → Каналы**

| Поле | Что вводить |
|---|---|
| bot_id | Выбрать из списка подключённых ботов |
| telegram_chat_id | ID канала из Telegram (отрицательное число для каналов) |
| title | Необязательно — подтянется автоматически |

**Перед сохранением:** бот должен быть **админом** в канале с правом
**«Приглашать»**. Иначе авто-выдача доступа после оплаты не сработает.

### 1.3 Продукт (Product)
Раздел: **Каталог → Продукты**

| Поле | Тип | Описание |
|---|---|---|
| name | string, ≤255 | «Премиум-клуб», «Курс по Python» и т.п. |
| code | string, 4–64 символа, **уникальный** | Используется в deep-link `/start?start={code}`. Только латиница, цифры, `_`, `-` |
| description | string, опционально | Подробное описание продукта |
| cover_url | URL, опционально | Картинка-обложка |
| currency | enum: `RUB` / `USD` / `EUR` | Валюта тарифов |
| price_3m, price_6m, price_12m | decimal | Цены за 3, 6, 12 месяцев |
| channel_id | int | К какому каналу выдаётся доступ |
| is_active | bool, default true | Если false — продукт не показывается в каталоге |
| default_funnel_id | int, опционально | Воронка, которая стартует автоматически когда юзер оставляет заявку (см. §6) |

**Code не должен совпадать с slug любой tracking-ссылки** — система
проверяет конфликт.

## 2. Создание воронки

Раздел: **Воронки → + Новая воронка** (или прямо через мастер).

### 2.1 Поля воронки

| Поле | Тип | Default | Описание |
|---|---|---|---|
| name | string, 1–255 | — | «Прогрев на покупку клуба», «Реактивация после месяца молчания» |
| description | string | null | Внутренняя заметка для команды |
| product_id | int | — | К какому продукту относится воронка |
| bot_id | int | null | Через какого бота шлём. Если `null` — берётся первый активный (best-effort) |
| ttl_days | int, 1–365 | 90 | Максимальная длительность воронки. Юзер не получит сообщения, попавшие за пределы TTL |
| cancel_on_payment | bool | true | Отменять воронку при создании Payment по этому продукту. Рекомендуется оставить включённым |
| is_active | bool | false | **Воронка не работает, пока is_active=true.** Активируется на секции «Запуск» в студии |

### 2.2 Шаблоны при создании
Мастер предлагает 3 шаблона, заполняющие начальные шаги:
- **welcome** — приветствие + знакомство
- **sales** — серия с офером и call-to-action
- **nurture** — мягкий прогрев без жёстких продаж

Шаблоны — стартовая болванка, тексты после создания можно переписать.

## 3. Шаги воронки (FunnelStep)

Студия: **Воронки → {воронка} → секция «Шаги»**.

Каждый шаг — одно сообщение бота, которое уйдёт через `delay_minutes`
после старта воронки для юзера.

### 3.1 Поля шага

| Поле | Тип | Описание |
|---|---|---|
| order_idx | int | Позиция в воронке, начинается с 0. Меняется drag-n-drop в списке слева |
| delay_minutes | int, ≥0 | Задержка от **момента старта воронки для юзера** (НЕ от предыдущего шага). В UI выбирается «N минут / часов / дней» |
| message_text | string, 1–4000 | Сам текст. Поддерживает Telegram HTML и плейсхолдеры (см. §3.2) |
| parse_mode | enum | `HTML` (по умолч.) / `MarkdownV2` / `null` |
| media | array, 0–10 | Файлы шага (см. §4) |
| buttons | JSONB, опционально | Inline-кнопки (см. §5) |
| is_active | bool, default true | Если false — шаг пропускается при отправке (черновик) |
| lead_magnet_id | int, опционально | Legacy: одна привязка к старой библиотеке Лидмагнитов. **Используйте `media` вместо этого** |

### 3.2 Telegram HTML — поддерживаемые теги

В `message_text` можно использовать:

```
<b>жирный</b>            <i>курсив</i>
<u>подчёркнутый</u>      <s>зачёркнутый</s>
<code>моноширинный</code>
<pre>блок кода</pre>
<blockquote>цитата</blockquote>
<blockquote expandable>раскрывающаяся цитата</blockquote>
<tg-spoiler>спойлер</tg-spoiler>
<a href="https://example.com">ссылка</a>
```

**Двойной перенос строки** = новый абзац. Одинарный = перенос внутри абзаца.

### 3.3 Плейсхолдеры

В тексте автоматически подставляются данные клиента:

| Плейсхолдер | Чем подменяется | Пример |
|---|---|---|
| `{first_name}` | Имя из Telegram-профиля | Иван |
| `{username}` | @username из Telegram | ivan_pro |

Если значения нет — подменяется пустой строкой (`{username}` для юзера
без @username станет пустым). Защитный приём: «Привет{first_name, }!» —
если имени нет, получится «Привет!»; если есть — «Привет, Иван!».

### 3.4 Лимиты длины

| Кейс | Максимум |
|---|---|
| `message_text` для шага без media | **4000 символов** (Telegram-лимит 4096) |
| `message_text` для шага с **media** | **4000** (всё равно идёт отдельным сообщением до/после альбома) |
| Caption под одиночным медиа (фото/видео + текст) | **1024 символа** Telegram |

Если у шага одно медиа и текст ≤ 1024 — текст приклеится к медиа как
caption. Если >1024 — текст пойдёт отдельным сообщением.

## 4. Медиа в шагах (FunnelStepMedia)

Каждый шаг может содержать **0–10 файлов**. Если 0 — шлётся обычное
текстовое сообщение. Если 1 — медиа с подписью и кнопками. Если ≥2 —
**media-group (альбом)** + отдельное text-сообщение с кнопками.

### 4.1 Поддерживаемые форматы

| Тип | MIME | Расширения | Лимит размера |
|---|---|---|---|
| **photo** | `image/jpeg`, `image/png`, `image/webp` | jpg, jpeg, png, webp | **10 MB** |
| **animation** (GIF) | `image/gif` | gif | 50 MB |
| **video** | `video/mp4`, `video/quicktime`, `video/webm` | mp4, mov, webm | 50 MB |
| **audio** | `audio/mpeg`, `audio/mp4`, `audio/ogg`, `audio/wav` | mp3, m4a, ogg, wav | 50 MB |
| **document** | всё остальное (PDF, ZIP, docx, ...) | любое | 50 MB |

**Hard cap upload-формы — 2 GiB.** Для файлов > 50 MB Telegram Bot API
отказывает в `sendVideo`/`sendDocument` (нужен Local Bot API). Сейчас
такие файлы будут отвергнуты с понятной ошибкой при загрузке.

### 4.2 Дополнительные поля каждого медиа

| Поле | Описание |
|---|---|
| `caption` | Подпись под этим конкретным файлом. Для альбомов отображается **под каждым медиа** отдельно. ≤ 1024 символа |
| `order_idx` | Порядок в альбоме (0..9). Меняется drag-n-drop |
| `telegram_file_id` | Автокэш после первой отправки. **Не вводится руками** |
| `thumbnail` | Авто-кадр для видео (генерируется ffmpeg'ом) |

### 4.3 Логика отправки

| Количество медиа | Что Telegram получит |
|---|---|
| 0 | `sendMessage(text, buttons)` |
| 1 (photo) | `sendPhoto(photo, caption=text, buttons)` |
| 1 (video) | `sendVideo(video, caption=text, buttons)` |
| 1 (document) | `sendDocument(doc, caption=text, buttons)` |
| ≥ 2 | `sendMessage(text, buttons)` **первым** → `sendMediaGroup([media])` после |

## 5. Inline-кнопки (ButtonsEditor)

Кнопки опциональны. Каждая — это **тип действия + текст** (то, что
видит юзер) + параметр (если нужен).

### 5.1 Структура: ряды и кнопки в ряду

`buttons` — двумерный массив:

```json
[
  [ { "text": "Купить", "url": "https://pay.example.com" } ],
  [
    { "text": "Подробнее", "callback_data": "prod:5" },
    { "text": "Заявка",    "callback_data": "lead:5" }
  ]
]
```

Один **внешний** массив = ряды (одна строка кнопок).
Один **внутренний** массив = кнопки в ряду (отображаются горизонтально).

Сумма кнопок в одном ряду — желательно не более 3 (длинные тексты не
помещаются на узких экранах).

### 5.2 Типы кнопок (в админке dropdown)

| Тип | Поле | Что делает |
|---|---|---|
| 🔗 **Открыть ссылку** | `url` | Любой `https://…`, `tg://…`, `mailto:…`. Открывается в браузере или Telegram |
| 📝 **Оставить заявку** | `callback_data = lead:{product_id}` | Создаёт Lead в админке + автозапуск default-воронки продукта |
| 💎 **Показать тарифы** | `callback_data = prod:{product_id}` | Бот шлёт карточку продукта с ценами 3/6/12 |
| 🎯 **Запустить воронку** | `callback_data = funnel:start:{funnel_id}` | Подписывает юзера на указанную воронку (идемпотентно — повторно не дублирует) |
| 🏠 **Главное меню** | `callback_data = "menu:main"` | Бот шлёт каталог всех активных продуктов (то же, что `/start` без параметров) |

**Все callback_data, кроме перечисленных, бот игнорирует** — клики
«проваливаются в пустоту». Только эти 4 callback'а + 1 системный
(`unsubscribe_notifications`).

### 5.3 Системная кнопка

К каждому шагу автоматически добавляется системная кнопка:

```
🔕 Не присылать напоминания
```

Нажатие выключает `notifications_enabled` у юзера — он больше не
получит ни одного сообщения от любой воронки этого бота, пока
кто-то не включит обратно вручную. **В админке настраивать не
нужно**, она появится сама.

### 5.4 Ограничения текста кнопки

| Параметр | Лимит |
|---|---|
| `text` | до 64 символов (Telegram-лимит). На практике используйте до 25 — иначе обрежется |
| `url` | стандартный URL |
| `callback_data` | до 64 байт. С нашими шаблонами укладывается всегда |

## 6. Точки входа в воронку

Как юзер попадает в воронку:

### 6.1 Default funnel у продукта
Если в **Каталог → Продукты → {продукт} → default_funnel_id** указана
воронка — она **автоматически** стартует при создании Lead (юзер нажал
«Оставить заявку» в боте или клик на кнопку с `lead:{id}`).

Это **самый частый способ**: настройте раз и забудьте.

### 6.2 Tracking-ссылка
Раздел: **Воронки → {воронка} → секция «Точки входа» → Trackable Link**.

| Поле | Описание |
|---|---|
| utm_source | `instagram`, `youtube`, `tg_chat`, `podcast`, `email` |
| utm_medium | `reels`, `post`, `stories`, `video`, `email`, опц. |
| utm_campaign | `spring_2026`, `launch_day_1` — опц. |
| utm_content | опц. — для A/B вариантов |
| funnel_id | какую воронку запустить |
| product_id | какой продукт показать |

После сохранения система выдаёт URL вида `https://t.me/{bot_username}?start={slug}`.

**Что происходит:** юзер кликает → попадает в бот → бот сразу
показывает карточку продукта **+** молча стартует воронку → в аналитике
видна атрибуция по UTM.

### 6.3 Кодовое слово
Раздел: **Воронки → Кодовые слова → + Добавить слово**.

| Поле | Описание |
|---|---|
| word | Короткое слово без пробелов: `КЛУБ`, `ВЕБИНАР`, `СТАРТ`. Уникально на уровне БД (case-insensitive) |
| funnel_id | Какую воронку запустить |

**Что происходит:** юзер пишет в бот текстовое сообщение со словом
(в любом регистре) → бот отвечает «Слово принято» → запускается
воронка. Удобно для **эфиров и подкастов**, где ссылку нельзя
прикрепить голосом.

### 6.4 Кнопка «Запустить воронку» в другой воронке
Из любого шага воронки можно ссылкой запустить **другую** воронку —
тип кнопки 🎯 **Запустить воронку**. Это полезный приём «разветвлений»:
после «общей» воронки можно перевести юзера в специфичную ветку
(«хочу подробнее про продукт А» / «расскажите про продукт Б»).

## 7. Жизненный цикл одного юзера в воронке (FunnelEntry)

```
[Запуск точкой входа] → FunnelEntry status=active
       ↓
   Worker раз в N минут проверяет ScheduledMessage
       ↓
       ├── Все шаги отправлены → status=completed
       ├── Юзер сделал Payment + cancel_on_payment=true → status=cancelled, reason=paid
       ├── Прошёл TTL → status=cancelled, reason=ttl_expired
       ├── Юзер отписался → status=cancelled, reason=user_unsubscribed
       └── Менеджер отменил вручную → status=cancelled, reason=manual
```

Один юзер не может попасть в одну и ту же воронку дважды
**одновременно**: повторный запуск той же воронки игнорируется (но
другие воронки запускать параллельно можно).

---

## 8. Чек-лист перед активацией воронки

Когда переключаете `is_active = true`, убедитесь:

- [ ] Все шаги имеют непустой `message_text` и нет «битых» плейсхолдеров
      (`{firstname}` без подчёркивания — типичная опечатка)
- [ ] Все медиа загружены (нет «Медиа удалено» в превью)
- [ ] Все кнопки имеют корректный тип и заполненное поле:
  - URL-кнопка → URL начинается на `https://` или `tg://`
  - Lead / Product / Funnel → продукт/воронка выбраны
- [ ] У воронки выбран `bot_id` (или хотя бы один бот в системе активен)
- [ ] У продукта воронки правильно настроен `channel_id` и бот — админ
      этого канала
- [ ] `ttl_days` достаточен для последнего шага (если последний шаг
      через 30 дней, а ttl_days = 14 — последний шаг никогда не уйдёт)
- [ ] Прошли **тестовый прогон**: секция «Запуск» → «Тестовый прогон» →
      бот пройдёт всю воронку для вас за минуту (тестовые прогоны
      исключены из аналитики автоматически, `source=manual`)

После активации воронка работает для **новых** юзеров. Уже подписанные
юзеры (если бы воронка раньше была активна) продолжают по своим
запланированным сообщениям — даже если вы деактивируете воронку, их
очередь не сбросится. Для остановки всех — есть отдельное действие
«отменить всех активных» (в секции запуска).

## 9. Готовые шаблоны воронок

### 9.1 Прогрев перед покупкой (5 шагов)

| # | Задержка | Идея текста | Медиа | Кнопки |
|---|---|---|---|---|
| 1 | 0 (сразу) | Приветствие, что юзер получит из подписки | 1 фото обложка | 🏠 Главное меню |
| 2 | через 1 час | Кейс / отзыв клиента | 1 видео отзыв | 💎 Показать тарифы |
| 3 | через 1 день | Закрытие 2-3 типовых возражений | 1 фото с инфографикой | 💎 Показать тарифы |
| 4 | через 3 дня | Лидмагнит-чеклист (документ PDF) | 1 PDF | 📝 Оставить заявку |
| 5 | через 7 дней | Финальный оффер + дедлайн | 1-2 фото | 📝 Оставить заявку + 🔗 Связаться с менеджером |

### 9.2 Реактивация после неоплаты (3 шага)

| # | Задержка | Идея текста | Кнопки |
|---|---|---|---|
| 1 | через 2 дня | «Видел, вы интересовались. Что не подошло?» | 🔗 Связаться с менеджером |
| 2 | через 5 дней | Социальное доказательство — успех клиента | 💎 Показать тарифы |
| 3 | через 10 дней | Спец-предложение или скидка (если применимо) | 📝 Оставить заявку |

### 9.3 Объяснительная воронка после первой заявки (2 шага)

Запускается автоматически (default_funnel у продукта). Цель — пока
менеджер не связался, дать юзеру полезную инфу.

| # | Задержка | Идея текста | Медиа | Кнопки |
|---|---|---|---|---|
| 1 | через 5 минут | «Заявка принята! Пока ждёте менеджера — вот видео о том, как работает наш клуб» | 1 видео ≤ 5 мин | 🏠 Главное меню |
| 2 | через 1 час | «Менеджер скоро напишет. Если срочно — связь напрямую» | — | 🔗 Telegram менеджера |

## 10. Промпт для AI-ассистента (минимальный набор данных)

Чтобы AI собрал готовую воронку, ему нужно от заказчика:

1. **Имя продукта** и **краткое описание** (что продаёте).
2. **Целевая аудитория** (1-2 фразы).
3. **Главная боль клиента** и **как продукт её решает**.
4. **Социальное доказательство** (1-2 кейса или цифры).
5. **CTA** — что клиент должен сделать (заявка / оплата / звонок).
6. **Тарифы** — короткое описание тарифов 3/6/12 мес.
7. **Tone of voice** (формальный / дружеский / экспертный).
8. **Имеющиеся медиа** — что есть готового (фото, видео, кейсы, PDF).

После этого AI генерирует:
- 5–7 шагов воронки с готовыми текстами (HTML-форматирование)
- Правильно подобранные типы кнопок к каждому шагу
- Рекомендации по timing'у (delay_minutes)
- Маппинг существующих медиа на шаги

## 11. Команды и адреса (для AI-агента, который работает через API)

| Действие | HTTP | Путь |

## 12. Типичные ошибки и как избегать

| Проблема | Причина | Решение |
|---|---|---|
| Шаг не отправляется | Битая inline-кнопка без url И без callback_data | Worker автоматически фильтрует, но проверьте сами — в админке dropdown типа должен быть выбран и поле под ним заполнено |
| Шаг не отправляется, error `chat not found` | Юзер не контактировал с **этим** ботом. У воронки `bot_id=null` → fallback на любого активного → ошибка | Привяжите конкретный бот к воронке: `funnel.bot_id` |
| Шаг отправился, но без медиа | Файл удалён с диска / повреждён | Проверьте в админке: миниатюры должны быть видны. Если есть «?» — перезагрузите |
| Бот «не понимает» нажатие на кнопку | `callback_data` не из списка `lead/prod/funnel:start/menu:main` | В админке выберите тип из dropdown, не вводите callback вручную |
| `is_active = true` не помогает — новые юзеры не получают сообщения | У продукта не указан `default_funnel_id`, нет tracking-ссылок, нет кодовых слов | Настройте хотя бы одну точку входа (§6) |
| Слова `{first_name}` остаются буквально | Опечатка: `{firstname}` без подчёркивания, `{name}` и т.п. | Только два рабочих placeholder'а: `{first_name}` и `{username}` |
| Caption обрезан в Telegram | Длина > 1024 символов под одиночным медиа | Сократите или используйте шаг без медиа (тогда лимит 4000) |
| После загрузки видео в превью «▶» вместо кадра | Thumbnail ещё не сгенерирован (1-3 сек) или ffmpeg упал | Обновите страницу. Если не помогло — формат не распознался, перекодируйте в mp4 |
